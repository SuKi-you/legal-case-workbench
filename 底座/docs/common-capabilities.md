# 共用能力

共用能力与插件宿主统一放在“底座”工程中。原“共用能力插件”目录的说明已归入本页，源码、依赖和运行入口统一管理；内部仍按职责划分模块。

当前材料登记、原件保存、OCR、人工文字修订和固定版本引用源码在[材料模块](../src/materials)，统一入口在[runtime.ts](../src/runtime.ts)。IDE 支持导出文字后直接编辑、保存为新版本，以及创建和核对引用；在线编辑页面仍在最终 Web 阶段接入。运行方法与当前边界见[底座说明](../README.md)。

案件管理源码在[案件模块](../src/cases)：按案件独立保存材料、版本、引用与原始附件，支持案件检索、持续存取和手工进度标记；全案保存点支持预览、恢复与撤销回滚，保留原件和历史。旧全局材料保留原位，不自动归案；原始 PDF/Word 附件仅存取、不解析。案件管理页面仍在最终 Web 阶段接入。

已有[需求与核对循环控制器](../src/loops/engine.ts)，由上层协调专业需求/复核与读取能力；固定材料版本、核验出处、约束重复任务和预算，并保存逐轮轨迹。`demo:loop` 继续用确定性 test 提供方验证机制，详见[loop 说明](intake-loop.md)。

本轮在[信息模块](../src/information)实现四项功能：按需求整理人物、时间、事件与关系；跨材料关联与语义归组；在同一可比事项下核对冲突；检查专业需求已有、缺失和待复核的信息。DeepSeek 负责文本理解；代码校验出处、规范金额和日期，单独的模型调用逐条复核需求相关性、原文支持、角色与肯否，之后才接纳候选用于比较和需求核对。来源标签不代表材料已经鉴真，语义复核也可能漏错。

代码已实现，已完成有限的独立虚构材料验收，结果与限制见[信息整理说明](information.md)。普通运行时仍默认 32 个能力，信息任务按配置额外装配 3 个能力；结果随案件保存、重读并参与全案回滚。`information -- run` 执行，`show` 离线查看 JSON，`demo:information` 使用虚构材料实际调用已配置的 DeepSeek API。

本轮（2026-11-02）补齐两项共用能力初版：

- [会话与执行](../src/agent)：终端连续任务、模型选择已注册工具、输入和案件范围检查、回复语义复核，以及处理中步骤的不可变快照。整理的读取/复核边界也可恢复；写操作先核对回执，预算不因重启清零。
- [成果整理与导出](../src/outputs)：统一事实版底稿、材料索引、时间线、冲突/缺项、来源附录、专业插件区块和版本差异，保存并导出 Word、Markdown、JSON。

使用方法与真实模型虚构验收见[终端执行与成果导出](execution-and-outputs.md)。会话快照与案内底稿均纳入全案保存点，外部导出副本继续保留。底稿分别标明快照是否仍一致、分析是否覆盖当前材料，以及未覆盖/有分支/未解析的范围；PDF/Word 原始附件当前不自动解析。

部门法插件可沿统一接口贡献工具、信息需求配置和带出处的专业成果区块，无需重复实现会话、存储、恢复和格式导出。专业内容仍需承办人复核。自我进化继续后置；两大业务阶段仍为接案与材料整理、关键节点审查与准备，均先在 IDE 验收，Web 最后，不使用 Dify。
