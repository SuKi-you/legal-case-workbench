# 信息整理与核对：使用与实现

本模块在已有 loop 上实现四项共用能力：按专业需求提取人物、时间、事件和关系；跨材料关联及同义记录归组；比较可比记载的冲突；核对专业需求的已有、缺失及待复核信息。模型负责理解文本，代码负责范围、引用、规范化、比较与提交约束。自我进化仍后置。

## 本次验收结果（2026-11-01）

代码已完成初版；类型检查、构建及 **364 项自动化测试全部通过**，无跳过。构建产物另验证结构化运行、重启读回、全案回滚、撤销及真实模型运行记录读回，默认 32 个能力保持可用。机制检查使用确定性测试模型，与下列真实模型验收分开。

使用用户本地配置的 DeepSeek，三组独立虚构材料分别通过逐来源评分。每条输出都要匹配允许的事实，每项预期事实均须覆盖；同时检查具体冲突来源对、身份归组、必要字段、读取范围和最终状态。

| 场景 | 实际结果 | 模型端口调用数 |
| --- | --- | --- |
| 同一交易三份记载 | 1.25 万元与 12500 元归为等价表达；分别与 12000 元形成两处记载冲突，结果为待复核。 | 6 |
| 同名人员、不同月份与口径 | 4 条金额记录按来源保留，不把两个明确身份合并，不把不同月份及税前/实发差异误报为实际冲突。 | 8 |
| 口头讲话和后续联系 | 3 条相关记录；保留陈述者与原讲话者、“上周”的未知日期和后续未联系的期间，不混入书面通知事项，不重复追问已有陈述。 | 11 |

重要限制：这三组是分别完成后重新评分汇总的结果。一次整套运行在第三组的高推理复核上触发 **90 秒超时**；将该次验收的单调用时限设为 **180 秒**后通过。失败报告保留，不算通过；本次没有证明稳定的响应时长，也没有完成真实卷宗或专业法律质量评测。

```powershell

npm.cmd run demo:information
```

此命令读取 `.env.local` 中的 DeepSeek 配置，实际调用 API，有调用费用。输入仅为代码内的三组虚构材料：同一交易的金额冲突、同名不同身份/月份/口径，以及口头讲话和后续联系陈述。验收预期单独留在评分侧，不传给模型。输出案件、运行 ID、调用数及通过/失败；报告保存在 `runtime-data/evaluations`，失败也保留，不覆盖为成功。

## 整理自己的案件

先用已有 `cases` 命令创建案件、登记材料，或为图片执行 OCR，必要时直接编辑文字。明确选择本次使用的文字版本；原件、OCR 及修订版本互相保留，没有自动 `latest`。

建立 UTF-8 JSON 计划，例如：

```json
{
  "goal": "核对这笔付款的各份记载",
  "selections": [
    { "materialId": "替换为材料UUID", "versionId": "替换为文字版本UUID" }
  ],
  "needs": [{
    "id": "payment.amount",
    "question": "这笔付款的实际到账金额是多少？",
    "reason": "需要对照同一交易的金额记载",
    "spec": {
      "topic": "payment.actual_received",
      "subject": null,
      "object": null,
      "period": null,
      "basis": "实际到账",
      "requiredFields": ["subject", "event.key", "time", "value", "basis"],
      "minimumSupport": "statement",
      "applicable": true
    }
  }],
  "limits": { "maxRounds": 4, "maxReads": 12 },
  "maxModelCalls": 24
}
```

占位字符串须替换为实际 UUID。纯文本原文的 `versionId` 等于 `materialId`；OCR、人工修订有各自版本 ID。随后运行：

```powershell
npm.cmd run information -- run --case '<案件ID>' --plan './plan.json'
npm.cmd run information -- show --case '<案件ID>' --run '<运行ID>'
```

`run` 会把选定文字发送给配置的模型服务；`show` 仅读取已保存结果，不需要 API 密钥或网络。默认数据目录为 `./runtime-data`，两条命令都可指定 `--data-dir`。Ctrl+C 取消；失败、来源改变、预算耗尽或在案件原子提交开始前取消，都不会把本次未完成结果写入案件。原子提交开始后以提交结果为准，已经保存的记录可用案件保存点回滚。

## 底座和专业插件分别贡献什么

专业提供方声明 `question/reason/spec`：当前事项是什么、指向谁、哪个期间或口径、哪些字段必要、只需陈述还是还需文件支持、是否适用。底座不内置劳动法字段或把字段空缺自动当成追问理由。

`createInformationPlugins({ model, needs, bindings?, extraction? })` 把这些差异装配成声明、读取和复核三个能力，与现有宿主协议一致。当前有一套通用的声明式复核；实际法律插件仍需贡献专业规则与业务判断，不能用字段齐全代替法律专业结论。

`organizeCaseInformation({ dataDir, caseId, plan, model, signal? })` 为 CLI 和将来网页提供同一个服务入口。`JsonModel` 是可替换资源端口，当前实际接通 DeepSeek。普通 `createRuntime` 默认仍有 32 个能力；信息任务按配置额外装配 3 个能力，读取和调用预算不会影响未执行的其他案件。

## 从输入到入库

1. 固定案件版本及材料的 `materialId/versionId/textSha256`；每个读取任务明确选定来源。
2. 按片段带着需求读取，模型返回结构化候选和逐字摘录。超过片段预算明确失败，不能静默跳过材料。
3. 代码校验片段归属、逐字引用和 UTF-16 位置；必要身份字段有同片段上下文时附加真实上下文引用。金额用十进制字符串规范化，日期按原文解析，相对时间保留未知。
4. 默认另一次模型调用逐条复核需求相关性、原文支持、statement 与结构命题的一致性、角色及肯否；DeepSeek 复核请求启用高推理。必须逐条明确通过；失败反馈原因后有限纠正，仍失败整批拒绝。复核与纠正均消耗统一模型调用预算。模型复核改善约束，但仍可能漏错。
5. 比较规范记录，保留所有原话及出处，再核对各需求的读取范围、必要字段、支持类型和冲突情况。仍有选定材料未查时先读材料，已有陈述不因缺少独立印证被当成未提供。
6. loop 明确完成、待复核、无新动作或轮数/读取预算耗尽。已结束运行按起始案件版本提交；并发修改或回滚导致输入过期时拒绝迟到结果。

默认每次提取最多修复 1 次，可设 0–2；每片段最多 5000 字符，默认最多 32 个片段。默认任务最多 4 轮、12 次读取、24 次实际模型调用。调用超时、网络重试与取消由 DeepSeek 适配器处理；所有限制均有明确错误或退出状态。

## 四项结果怎样理解

| 能力 | 当前结果与边界 |
| --- | --- |
| 人物、时间、事件与关系 | 每条记录保留参与者、陈述归属、事件、时间、数值/内容、肯否、期间、口径、来源类型与未知项。按明确日期可供后续时间线展示；当前不另建时间线页面。 |
| 跨材料关联和语义归组 | 使用结构化含义而非原句字符串，识别金额等价和同一事件；原话不删除。同名仅列候选，明确身份标识或人工别名绑定才能确认主体关联；同文字副本不能当作独立佐证。 |
| 冲突核对 | 同一可比事项的金额、时间或肯否不同可列不一致；人物、期间、币种、口径不同先列范围差异；条件缺失或文字语义不明列疑似/上下文不足，不决定哪方真实。任意长文本的逻辑矛盾仍有能力边界。 |
| 专业需求核对 | 分开记录读取覆盖、内容一致性、支持类型与满足状态。只在已查范围说“未找到”；缺少文件支持时保留已有陈述，仅补查对应材料。未知信息不自动等于不存在。 |

`bindings` 可显式声明人工确认的名称对应及理由；不能用别名强行合并两个同类标识不同的人。`sourceKinds` 可按材料 ID 指定 `party_statement` 或 `document_record`，未指定按陈述处理，推断不能借标签提升。该标签只描述材料类型，不是鉴真、证据能力或证明力结论。

## 保存与后续范围

`LoopRun.findings` 保存记录，`LoopRun.information` 保存主体归组、关联、冲突和逐需求核对；每轮复核也保留当时分析。它们与原 loop 一同纳入全案保存点、恢复及撤销，重新打开仍校验材料版本与内容。

本文记录四项能力初版及其有限虚构材料验收，不能据此宣称复杂真实卷宗或跨部门法质量已经验证。后续已在同一底座完成连续终端对话、注册工具调度、读取/复核检查点恢复，以及带出处的材料底稿导出，见[执行与成果导出说明](execution-and-outputs.md)。劳动法等专业规则、完整接案业务、关键节点审查和 Web 继续按规划推进；自动训练和自我进化后置。

源码入口：`src/information/contracts.ts`（共享对象）、`extract.ts`（提取与语义入库检查）、`normalize.ts`（规范化）、`compare.ts`（关联与冲突）、`coverage.ts`（需求核对）、`plugins.ts`（插件装配）、`service.ts`（统一应用服务）、`deepseek.ts`（模型适配）。
