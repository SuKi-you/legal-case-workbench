# 终端执行与成果导出

更新：2026-11-02。本轮完成共用底座的“模型与执行支持”和“成果整理与导出”初版：可以在 IDE 终端提出案件任务，由模型选择已注册工具；执行过程留下检查点，重启后继续；整理结果可以保存为带出处的底稿，并导出 Markdown、Word 和 JSON。两块使用同一案件工作区，参加全案保存点、回滚及撤销。

本轮完成的是通用执行与交付能力。劳动法专业规则、完整接案任务和关键节点审查仍按原实现规划推进；网页放在最后，自我进化继续后置。

## 在 IDE 中开始使用

在 VS Code 的 PowerShell 终端进入底座目录：

```powershell
Set-Location -LiteralPath 'C:\Users\13700\Documents\LAW_Agent\法律agent3.0\底座'
npm.cmd run agent
```

程序会列出本机案件供选择。也可以直接指定案件 ID 或能唯一匹配的名称：

在“选择案件”提示后输入数字序号（例如 `1`）、案件名称或完整 ID；输错会重新提示，输入 `q` 可退出。进入后会显示“已进入 Agent 对话”和“你：”，这时再输入任务。若终端显示 `PS C:\...>`，表示当前是 PowerShell，应先执行 `npm.cmd run agent` 启动程序。

```powershell
npm.cmd run agent -- --case '<案件ID或唯一名称>'
```

进入后可直接输入：

> 整理本案现有材料，保留出处、冲突和未明确事项，然后生成一份底稿。

终端会显示实际执行的工具、读取与复核检查点，以及最终结果或停止原因。完成后显示会话 ID、任务状态和已使用的预算。连续输入下一条任务，可以继续同一案件；每个新任务与上一任务关联，原有对话、动作和结果保留。

首次使用还没有案件时，先创建并登记文字：

```powershell
npm.cmd run cases -- create --title '示例案件' --actor '你的称呼'
npm.cmd run cases -- add-text --case '<新案件ID>' --label '初次陈述' --text '在这里填写当事人实际提供的陈述'
```

模型使用本机 `.env.local` 的 DeepSeek 配置，处理案件时会把选定文字发送给该服务并产生调用费用。密钥保留在本地配置中，不写入会话和底稿。项目默认单次请求时限为 90 秒；复杂复核如超时，可将本地 `DEEPSEEK_TIMEOUT_MS` 调为 `180000`。

## 常用操作

| 操作 | 用途 |
| --- | --- |
| 普通文字 | 提出任务、提问或补充案情。实际补充的案情由工具逐字登记为新的用户陈述，不把 Agent 的回复当作原始材料。 |
| `/status` | 查看当前会话和任务状态。 |
| `/materials` | 查看当前案件的材料与附件。 |
| `/attach "完整文件路径"` | 选择允许本次任务导入的本地文件，随后再用普通文字要求登记、OCR 或处理。选择路径本身不会自动解析内容。 |
| `/resume` | 从已确认的执行检查点继续中断任务。 |
| `/quit` | 退出终端会话，保留已保存状态。 |
| `Ctrl+C` | 正在执行时中断当前任务；空闲时退出。 |

图片先登记，再调用 OCR 得到文字。原始 PDF、Word 等附件当前只按字节保存和取出，不会因上传或出现在材料目录中就被自动解析。底稿会保留未解析附件及未纳入整理的材料范围。

如果材料有多个文字分支，需要明确选择版本；底座不会仅按时间选“最新”。只有存在唯一文字分支时才自动选择。相对时间和日期不明的事项仍单列，不猜测具体日期。

## 关闭后怎样继续

记下终端显示的案件 ID 和会话 ID，重新进入：

```powershell
npm.cmd run agent -- --case '<案件ID>' --session '<会话ID>'
```

恢复已经中断的任务：

```powershell
npm.cmd run agent -- --case '<案件ID>' --session '<会话ID>' --resume
```

不调用模型，离线查看已保存状态或会话列表：

```powershell
npm.cmd run agent -- --case '<案件ID>' --session '<会话ID>' --status
npm.cmd run agent -- --case '<案件ID>' --sessions
```

每个完成的工具步骤以及整理 loop 的读取、复核边界都会保存。重启复用已经确认的步骤；尚未返回的模型请求需要重新发起。写操作先核对操作 ID、回执及案内结果，确认已提交就复用，不能确认时明确停止，避免重复写入。恢复不会把已消耗的预算清零。

补料或修订使输入发生变化时，继续操作会建立关联的新一轮处理，旧结果保留为历史，并重新核对当前范围。回滚恢复案件时，也恢复保存点内的会话快照和底稿集合；回滚前迟到的旧操作不能重新写入当前视图。

## 生成并导出底稿

Agent 可以通过自然语言调用 `output.create`。也可使用不调用模型的独立导出命令，从一个明确的整理运行生成底稿：

```powershell
npm.cmd run outputs -- create --case '<案件ID>' --run '<整理运行ID>'
npm.cmd run outputs -- list --case '<案件ID>'
npm.cmd run outputs -- show --case '<案件ID>' --output '<底稿ID>'
```

每一版包含案件概况、材料和附件索引、人物与事件关联、时间线、带出处的记载与陈述、冲突、专业需求覆盖和待核对事项，以及来源摘录。底座以统一内容结构生成 Word 和 Markdown，Word 是可编辑的 `.docx`，生成文件本身不要求安装 Office。

取出一份 Word 或 Markdown 副本：

```powershell
npm.cmd run outputs -- export --case '<案件ID>' --output '<底稿ID>' --format docx --out './runtime-data/exports/接案底稿-01.docx'
npm.cmd run outputs -- export --case '<案件ID>' --output '<底稿ID>' --format md --out './runtime-data/exports/接案底稿-01.md'
```

`--format json` 可导出结构化数据。导出不覆盖已有文件，也不允许把副本写回案件受管目录；使用新的文件名即可。所有命令默认使用 `./runtime-data`，可用 `--data-dir` 指定同一数据目录。

补料后生成新版时，指定上一版底稿，形成记录和需求状态的变化清单：

```powershell
npm.cmd run outputs -- create --case '<案件ID>' --run '<新整理运行ID>' --previous '<上一版底稿ID>'
```

底稿及其来源固定保存，旧版不会被新版覆盖。外部导出的副本也不随案件回滚而改写；副本中的版本标识可用于追溯。

## 怎样判断底稿是否反映当前材料

读取底稿时会同时返回两类检查，二者有不同含义：

| 字段 | 含义 |
| --- | --- |
| `currentInputMatches` | 生成底稿时记录的案件资料、材料和附件目录，与当前快照是否一致。 |
| `analysisCoversCurrentInput` | 固定整理运行是否覆盖当前各材料的唯一文字分支，且没有尚未解析的附件。 |
| `sourceCoverage` | 列出未覆盖材料、存在分支而未明确选择的材料，以及未解析附件的 ID。 |

一份刚生成的底稿也可能忠实整理的是旧运行或部分材料。快照一致不能直接理解为“所有材料已经读完”，更不证明材料真实或法律事实成立。两个标识和具体范围应一起查看；专业需求是否满足、是否存在冲突还要查看底稿正文。

## 插件怎样复用这两块

终端可加载本地模块导出的 `LegalAgentExtension`：

```powershell
npm.cmd run agent -- --case '<案件ID>' --plugin './examples/plugins/transfer-review.ts'
```

此模块仅为付款材料核对示例，不是劳动法插件。插件可贡献：

- 带用途、参数和读写性质的工具，供模型选择，仍由底座检查案件范围并执行。
- 信息需求配置 `profiles`，声明要检查的专业事项、字段、支持类型和理由。
- 带提供方、版本及案内记录引用的专业成果区块，附入统一底稿。

底座负责会话、执行、预算、来源、检查点、存储和格式导出，插件作者补入专业差异。插件分析会明确标为专业贡献并待承办人复核；引用一个案内记录，并不自动证明插件的法律分析正确。插件文件由使用者在启动命令中明确选择，模型不能自行加载任意本地模块。

## 源码位置

| 模块 | 职责 |
| --- | --- |
| `src/agent` | 会话、动作选择、回复复核及任务协调。 |
