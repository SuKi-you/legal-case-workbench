# 案卷工作台

法律 Agent 3.0 优化版的本地 Web 应用。左边是案件与材料目录，中间查看原件，右边校对识别文字和追溯出处。接案与关键节点审查共用案件资料和劳动法插件。

## 启动

使用 Node.js 24.12 或更新的 24.x 版本。在 VS Code 打开本目录，使用 PowerShell 终端运行：

```powershell
npm.cmd start
```

打开 [http://127.0.0.1:8787](http://127.0.0.1:8787)。首次运行前若底座尚未安装依赖，在本目录执行 `npm.cmd --prefix '../../底座' ci`。Web 端复用底座的依赖，无需单独安装前端框架。

底座的 `.env.local` 提供 DeepSeek 配置。未配模型时仍可建案、管理材料、做 OCR 和人工修订。运行接案核对时，确认后才会将列出的材料文字交给 DeepSeek。关键节点在本机对照已保存的核对轮次。OCR 在本机运行，首次可能需要下载语言模型。

## 办案路径

1. 通过左侧「建案」开始。可粘贴文本，上传 TXT、PNG 或 JPEG。PDF、DOCX 可以保存为原始附件，需另行录入正文才能参与核对。
2. 选中照片并运行 OCR。点击原件上的识别区定位文字，在右侧修改并保存。通过「版本记录」回看原稿、OCR 及每次修订。
3. 运行接案核对。核对结果区分已读内容、未核项和固定版本出处。点击出处可回到对应文字。
4. 补入答辩或新证据后，再运行一轮接案核对。在「关键节点」选定前后两轮，生成变化与准备事项。
5. 在「接案底稿」保存和查看底稿，通过「导出底稿」下载 Word、Markdown 或 JSON。已保存底稿是当时的材料快照。
6. 通过「案件进度」标记状态。在「版本记录」创建全案保存点，需要恢复时先预览变更，再执行回滚。

Web 案件默认保存在本目录的 `runtime-data/`。用 `LAW_WEB_DATA_DIR` 可指定其他存储目录，`LAW_WEB_PORT` 可改端口。启动时只监听本机回环地址，适用于单机使用。

## 复现验收

`npm.cmd test` 使用临时案件、Tesseract 和确定性的模型输入，检查材料原件、修订、插件核对、节点对照、底稿下载和全案恢复。测试首次需要 OCR 语言文件。有现成的 `chi_sim.traineddata` 和 `eng.traineddata` 时，可把 `LAW_WEB_OCR_CACHE` 指向其目录。
