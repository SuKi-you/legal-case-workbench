# Web 前两阶段验收

本验收面向本地 IDE 里的劳动争议接案与关键节点审查。主案沿用同一案号，执行接案、校对文字并登记答辩、补入新证据、庭前准备、恢复到接案保存点、撤销和新进程读回。三组材料均为虚构。真实 API 仅接收选定材料和正常业务输入。冻结的核查预期由验收程序单独读取。

## 用例与复现

| 用例 | 要核对的业务变化 |
| --- | --- |
| primary | 同一次口头解除通知有相反说法；校对扣项；正式书面材料明确生效日 |
| rephrased | 更换人名、时间、数额、材料顺序与表达，保留同范围异说与有效生效日 |
| other_scope | 复函针对另一人及另一事件；新材料只说明领取物品安排，解除日期仍待核 |

输入和预期的 SHA256 保存在[冻结清单](../需求与验收案例/pre-web-fixture-freeze.json)。在底座目录执行：

```powershell
node '../评测与验收/run-pre-web.mjs' --fixture primary
node '../评测与验收/run-pre-web-offline.mjs'
node --env-file-if-exists=.env.local '../评测与验收/run-pre-web.mjs' --live --source-kinds --fixture primary --model-calls 100
```

第一条仅核验冻结字节。第二条重放人工转录的结构化观察，执行实际比较、覆盖、劳动法复核和节点构造。第三条调用真实 DeepSeek，通过产品 CLI 执行四个工作流。它在新临时数据目录创建虚构案件，报告及阶段日志按每次运行写入 `优化实验-01/对照评测/pre-web`。可附加 `--natural-language-smoke` 验证普通对话调用案件材料目录。模型调用上限和实际调用量逐任务记录。

## 通过条件

| 观察项 | 检查方法 |
| --- | --- |
| 同案连续性 | 四步使用同一案件，后续底稿记录上一步底稿，节点的前后整理运行可定位 |
| 事实与范围 | 原话和双方证据可核对；不同人、事件或工资口径不构成同一项冲突 |
| 时间 | 只采用文件明确写出的生效日，谈话、出具、签收、到岗分别保留 |
| 未完成事项 | 逐需求台账区分已检查与未读，保留待办；无有效证据时不能声称事项已完成 |
| 底稿与准备 | JSON、Markdown、Word 都可读；当前版本正确；庭前从同案最新整理运行形成有出处的准备事项 |
| 保存恢复 | 接案保存点能退出后续结果；原始字节保留；撤销后能重新打开已存庭前底稿 |

报告分别记录任务是否完成、选定材料范围、读取未完成对数以及专业事项的待复核状态。冻结输入未覆盖复杂真实卷宗、当事人资料真实性或具体个案法律适用。离线重放只验证结构化记录之后的流程。付款凭证等为专门编写的虚构文字转录，接案轮通过底座版本机制验证校对，不把本轮文字输入记为一次新 OCR 实测。

## 验收报告模板

| 记录项 | 填写内容 |
| --- | --- |
| 版本和范围 | 代码版本、样本哈希、主案/变形、离线/真实模型、模型配置 |
| 接案 | 终端退出状态、模型调用、需读/已读/未读、底稿位置、保留缺项 |
| 答辩 | 同案关联、修订源、双方记录、待核 |
| 新证据 | 材料变化、生效时间及依据、仍未明确事项 |
| 庭前 | 来源范围、复用整理运行、更新后的准备清单 |
| 保存恢复 | 保存点、回滚、撤销、独立进程读回 |
| 未通过与复跑 | 保留初次记录，列出修正原因及复测是否使用同一输入 |
