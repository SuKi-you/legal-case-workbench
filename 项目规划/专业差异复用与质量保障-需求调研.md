# 专业差异复用与质量保障：现实需求核查

研究日期与资料截止：2026-10-31。性质：公开资料调研与项目研究判断，不是用户访谈、采购调查、产品试用或独立效果实验。

## 一、结论先行

**值得将这个问题纳入项目的重点研究课题；目前不足以据此认定我们的插件架构有独特性、优于普通模块化实现，或值得直接扩建成全领域平台。**

本次要核查的原始命题是：

> 开发者只提供某个领域的专业差异，能否复用公共能力，少开发一整套 Agent，同时保持成果质量？

需要分开判断其中几件事：

| 判断项 | 本轮结论 | 依据与保留 |
| --- | --- | --- |
| 法律团队是否希望沉淀和复用专业经验、流程及能力 | 有直接现实依据 | 国内存在明确招聘职责、专业团队实践和律协实操活动。 |
| 公共技术与领域内容分开建设，是否已有真实实践 | 有 | 国内律所应用、国外律所工作流平台及法律援助开源项目均有实例。 |
| “通用底座＋专业能力包”是否仍是空白概念 | 不能这样主张 | 商业 Skills／工作流产品与开源法律访谈框架已覆盖相近思想。 |
| 专业作者是否只需提供几份法条或提示词 | 没有证据支持 | 规则与流程建模、数据整理、维护、测试及专业复核仍需投入。 |
| 跨任务复用能否降低总投入，且专业质量不劣 | 本轮未找到直接同时验证两者的独立对照实证 | 产品介绍、自报提效、AI采用率和一般法律问答评测均不能代替该验证。 |
| 本项目现有底座是否已证明上述价值 | 没有 | 已完成的是技术接入、替换、校验与生命周期测试，未完成真实法律任务比较。 |

因此，记录为：**复用专业经验和维护质量有实务依据；降低总投入并保持质量的组合命题，以及本项目的竞争优势，仍待验证。**

## 二、谁在需要什么

本问题首先面向法律能力的作者与维护者：律所知识管理／创新团队、法律知识工程师、法律科技开发者，以及法院或法援组织的工具建设人员。案件承办人和当事人是其成果的使用者或受益者。

从资料可以作出的项目推断是：这些团队希望把自己的经验、范本、规则与流程变成可重复使用的工具，并控制集成、维护和复核工作。不能据此推断所有律师都愿意写插件，或中国中小律所愿意采购一个新平台。

原产品背景中的“888万件自然人自行提起的一审案件”，反映的是法律服务与表达问题，**不能拿来估算法律插件开发平台的需求或市场规模**。

## 三、国内需求与实践证据

### S1：法律能力封装已经进入具体招聘职责

来源：[建纬深圳招聘原页](https://www.jianweishenzhen.com/Join/Position)，页面相关职位更新于2026-09-07。

“法律Skills专家”岗位要求封装可复用法律能力，设计调用和质量标准，测试、校准并维护模块，联动产品与研发。

**支持：**存在明确的专业能力产品化岗位需求。**限制：**单一机构的招聘不等于已经聘用，更不证明平台采购意愿或全国需求规模。

### S2：国内专业团队已复用平台能力构建自己的应用

来源：[植德金融部应用回访](https://www.meritsandtree.com/Content/2024/12-26/1827028496.html)，2024-12-26，具名团队自述。

团队利用构建平台、工作流、知识库和技术开发制作月报助手；专业金融助手则依赖经验资料整理、持续维护和来源核查。

**支持：**公共技术与专业资产结合有真实组织实践。**限制：**自述没有完整开发、维护及复核成本对照；文中提速数字前后任务口径不同，本报告不据此计算收益。

### S3：专业人员正在尝试把经验制成可复用技能

来源：[济南律协专题活动记录](https://www.jinanlawyer.cn/news_details/2487.html)，2026-09-17。

活动围绕谈案、阅卷、文书，参会律师现场制作可复用 Skill，并讨论团队知识沉淀。

**支持：**专业作者路径已有实操需求。**限制：**培训和供应商参与的演示不代表长期生产采用，更没有证明交付质量或净节时。活动涉及建纬品牌，不将它与S1视作完全独立的客户样本。

## 四、必须正视的现有供给与反证

### S4：相近的法律 Skills 产品已公开提供

来源：[Legora Introducing Skills](https://legora.com/blog/introducing-skills)，2026-10-05。

其产品允许法律团队用自然语言Markdown、参考材料、模板和正反例编写技能，供Agent使用并在团队内共享、改造。

**含义：**“专业经验封装为能力包，复用同一Agent”已不是概念空白。**限制：**这是官方产品说明，不能据此认定客户配置成本已足够低，或质量已通过独立非劣验证；公开材料未说明的能力也不能直接认定产品没有。

自然语言Skill与本项目TypeScript插件的执行机制不同；它们解决相近的专业复用需求，仍应作为替代方式比较。

### S5：有律所自己确认使用共用工作流构建平台

来源：[Paul, Weiss 上线与共研公告](https://www.paulweiss.com/insights/firm-news/paul-weiss-partners-with-harvey-ai-on-new-ai-workflows-innovation)，2025-06-11。

律所确认上线Harvey自定义工作流，并参与分解流程、嵌入本所经验与边界。

**含义：**共用平台加专业定制已有真实客户实践。**限制：**合作发布不是独立成本与质量实验；大型美国律所不能代表中国中小所。Harvey现行介绍已更新更名，不能把当前全部功能追溯为2025年即有。

### S6：接案和法律援助相关的共享构建机制，也已有开源实践

来源：[Suffolk LIT Lab Document Assembly Line 项目文档](https://assemblyline.suffolklitlab.org/docs/get_started/)，页面未标发布日期，本次访问2026-10-31。

项目为法院和法援组织提供Docassemble上的共用运行代码、问题库、文书工具与开发支持，用于构建法律引导式访谈。

**含义：**法律工具建设中的共用机制有实际用途，亦有既存方案。**限制：**这是访谈与文书自动化项目，不能等同于动态法律Agent；开源或本地部署本身也不构成我们的独特性。

## 五、“保持质量”是一项实际工作，不是自动获得的属性

### S7：国内专业指引要求按任务和事实复核成果

来源：[上海律协企业法律顾问服务AI应用操作指引](https://www.lawyers.org.cn/new/common-detail?id=49835e6e3485429ba83efcc34fec0618)，2026-08-04发布，试行。

指引要求按具体任务调整输入与模板，核对事实、有效法律依据、推理、遗漏及可操作性，并保留律师专业判断。

**含义：**质量机制可提供共同支持，专业内容仍需配置与复核。**限制：**操作指引说明工作要求，不是插件架构效果研究。

### S8：独立监管调查提示，复核可能抵消生成环节的节省

来源：[VLSB+C研究主页](https://lsbc.vic.gov.au/research-centre/what-we-do/publications/generative-ai-use-legal-profession-findings-2025-victorian)及[原始报告](https://lsbc.vic.gov.au/sites/default/files/2026-04/VLS0801_Generative%20AI%20Use_Report_FA_WEB_0.pdf)，2026-04-20发布。

调查1,887名维州律师，响应率6.4%，经加权；回答质量保障问题的AI使用者中，76%自报对照其他来源核验。有非使用者表示复核耗时足以自行完成原工作。

**含义：**应测净投入。**限制：**自愿、自报且非中国样本；该比例不是准确率，也没有测插件开发成本。（报告印刷页14、23—24。）

### S9：统一流程不能预设为所有法律任务的正确路径

来源：[LawFlow 原始论文v2](https://arxiv.org/html/2504.18942v2)，2025-09-03，COLM 2025。

研究观察到人的流程更具迭代性，而被测LLM更倾向线性、穷尽执行。

**含义：**公共执行结构需允许选择、回退与人工判断。**限制：**研究来自法学生的企业设立情境模拟；场景有限，非中国诉讼或跨领域插件迁移实证。

### S10：有引用仍可能在法律意义上引用错误

来源：[Magesh等，Hallucination-Free? 原始论文](https://dho.stanford.edu/wp-content/uploads/Legal_RAG_Hallucinations.pdf)，2025年正式发表，测试针对2024年产品。

预注册评测区分答案正确与法律依据匹配；真实但错误辖区的材料仍可能构成失当依据。

**含义：**来源存在性检查不能代替法律适用校验。**限制：**不能把旧产品结果当作2026产品表现，也不是复用开发成本实验。

## 六、据此可提出的研究重点

以下是本项目的研究推断，**不是上述来源已经证明的结论，也不是“无人解决”的市场空白声明**。

建议把问题具体化为：

> 在明确的法律任务中，专业作者能否提供有适用边界、可测试、可维护的专业能力包，复用公共执行与质量保障机制，使构建、集成、更新和人工复核的总投入下降，同时不增加重大专业错误？

专业差异不能缩成几份法条或一段提示词。它可能包括任务目标、适用条件、专业规则与例外、程序要求、证据需求、模板、法源版本以及验收反例。

公共机制与专业内容的划分也只能通过实际任务验证：

| 可尝试共用的机制 | 仍须由专业作者提供并验证的内容 |
| --- | --- |
| 文档解析、材料定位、版本与修订记录 | 哪些事实有法律意义、何种变化需要重新判断 |
| 模型与检索接口、调用与运行状态 | 应检索哪些法源、适用地域与时间、专业处理策略 |
| 引用存在性与摘录一致性检查 | 法源是否有效、具有何种权威性、是否支持该命题 |
| 评测运行器、复核记录与发布检查 | 任务评分标准、重大错误定义、边界与反例、合格要求 |

“有引用”“通过schema校验”“能加载插件”均不是法律质量合格的充分条件。共享机制可以帮助执行检查，不能把专业验证成本直接消除。

## 七、怎么验证，才能避免做完才发现没有价值

### 比较对象

至少比较两种实现：普通模块化调用方案，以及本项目的公共结构加专业插件方案。两者使用同等模型、材料、专业规则和质量检查，不采用故意弱化的单一大Prompt基线。

条件允许时，再与可获得的现成Skills／工作流方式比较。公开产品介绍不能代替亲自试用，不能假装我们已经做过竞品对照。

### 任务与人员

先完成一个有限的劳动接案任务；再选择第二个领域的小任务检验真实复用，不必先开发第二个完整部门法产品。第二个任务及验收标准需由相应专业人员确定。

后续应让未参与底座编写的作者按文档接入，观察其是否需要开发者手把手帮助。开发样例与封存验收案例分开，按实际材料出现顺序输入，由专业人员尽可能盲审成果。

### 应记录的指标

- **构建投入：**领域知识整理、能力包编写、工程集成与调试工时。
- **维护投入：**规则或模板变化后，需要修改、复核及重新发布的工作。
- **总交付投入：**运行时间加人工检查、修订和返工时间。
- **专业质量：**关键事实遗漏、无依据结论、错误适用、程序性遗漏、来源错配及任务完成度。
- **接入成本：**是否修改宿主、复制整套流程、增加大量只对单一领域有效的公共字段。

先明确重大错误、质量非劣的可接受界限与成功条件，再开展比较；本轮没有编造节省比例、准确率门槛或统计显著性。

### 什么情况下不再坚持插件架构

- 普通模块化或现成方式同样容易扩展，而我们的装配与配置增加了总投入。
- 新领域反复要求大幅修改所谓通用机制，公共层难以稳定复用。
- 新增专业能力包的测试及复核负担抵消了构建节省，或重大错误增加。
- 收益主要来自更好的模型、知识或模板，却被误归因于插件形式。

若出现上述结果，应缩小或放弃插件化的核心卖点，保留有用的材料能力、专业资产与测试案例。实际能力实现应能独立调用，插件外壳只负责接入，减少架构选择失误的损失。

## 八、本次研究的边界与对当前项目的影响

已核查招聘、具名律所实践、行业活动、官方产品和客户公告、开源法律服务项目、专业指引及原始研究。证据支持存在复用和质量维护需求，但没有完成用户访谈、预算／采购意愿验证、真实案例效果对照，亦没有测量本项目的成本优势。

没有把AI采用率当成插件平台需求，没有把培训当成长期部署，没有把客户自述当作独立效果验证，没有把未公开功能当成竞品缺失，也没有把“本轮未找到直接实证”写成“全球没有研究”。

**记录决定：纳入重点研究问题，暂不认定为已成立的产品创新。** 当前薄底座维持已完成范围；本轮仅更新研究笔记，不继续编写共用或专业插件。接下来应由有限业务任务和公平比较决定通用层的边界，而非先扩大框架。
